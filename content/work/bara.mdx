## What it does

Four memory tiers — research memory, conversational state, a semantic profile and episodic memory in pgvector — with a policy layer that decides *whether* to retrieve, *from where* and *how much*, before any vector is compared. Every message is classified for intent and topic shift first; retrieval only sees that output.

## Why it exists

Production LLM systems tend to treat context as a sliding window and retrieval as always-on. BARA asks whether structured memory with deterministic gating measurably beats that.

## Evidence

A three-arm retrieval evaluation: 30 ground-truth queries against 605 chunks from 14 documents.

| Arm | MRR |
| --- | --- |
| Vector only | 0.7583 |
| BM25 + vector, RRF k = 60 | 0.7000 (−7.7%) |
| Hybrid + cross-encoder reranker | 0.7722 (+1.8%, ~0.86 s slower) |

The useful result is the negative one: at this corpus size, naive BM25 fusion pulls in lexical matches that aren't relevant. The reranker recovers it — at a latency cost.

## Limits

30 queries and 605 chunks are small. Relevance is judged by substring patterns with no inter-annotator agreement. The savings from *skipping* retrieval weren't measured because of provider rate limits. The "41 gates" are a hand-maintained table of decision points, not one gate construct.
