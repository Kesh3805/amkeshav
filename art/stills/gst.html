The answer is kept before anyone asks for it

Primary contributor · employer work · Aug 2025 – present

A returns dashboard for accounting firms: for each client GSTIN and tax period, where does every return stand?

The read path used to work out every status on every request, asking each source for each client and period on screen. So it slowed down at exactly the moment it was needed: near filing deadlines. The fix inverted the direction of the work.

1

The event names a key, never a change

A writer announces only which row is stale: account, GSTIN, period. The projector then reads the sources as they are now and rewrites that row.

So a duplicate event changes nothing, and two events arriving out of order still converge on the same row. An event carrying a change ("draft → filed") would have to arrive exactly once, in order.

The same path is the rebuild: recomputing a period is sending one key per row.
